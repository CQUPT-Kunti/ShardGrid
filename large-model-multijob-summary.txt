Large Model + Multi-Job Stress Gate Summary
Date: 2026-09-04

Scope
- Added a configurable large PyTorch model: LargeResidualTransformer.
- Integrated the model into automatic planning and automatic training.
- Added GPU reservation handling for multi-job conflicts.
- Added real multi-host hardware gate tests for Large-B and multi-job contention.

Why the control machine appears to hang
- The heavy work starts on the control machine before remote training begins.
- Automatic planning builds the large model locally and runs local profiling/tracing.
- The current flow builds/profiles the large model more than once:
  - hardware gate helper estimate_large_model()
  - JobManager automatic planner build_model_profile()
- build_model_profile() executes one real local forward pass with sample inputs.
- For Large-B, memory_bank_rows is scaled from live usable VRAM, so the local model can be multi-GB.
- Result: local RAM pressure, paging, and long periods without stdout, which looks like a hang.

Key fixes made in this round
- Added examples/models/large_residual_transformer.py.
- Wired model.parameters into config loading.
- Added large_residual_transformer support in JobManager automatic workload selection.
- Added large_residual_transformer support in examples/models/train_automatic_plan.py.
- Fixed automatic training loss path to use cross-entropy for token targets.
- Fixed rank0 stage probe batch shape mismatch in automatic pipeline training.
- Switched large model checkpoints to metadata_only during this gate to avoid multi-GB scp artifact transfers.
- Added StatusStore GPU reservation/release support.
- Made planner worker eligibility reject zero-usable-memory reserved GPUs before partition search.
- Added hardware tests for:
  - Large-B automatic 2-worker gate
  - multi-job reservation/rejection gate

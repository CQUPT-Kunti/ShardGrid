# T061 — Validate automatic discovery before launch

Phase: Phase 7  
Priority: P0 BLOCKING  
Depends on: T060

真实 Task 文件：

```text
tests/integration/test_generic_resource_discovery.py
src/shardgrid/control/resource_manager.py
src/shardgrid/resources/models.py
```

## 目标

验证每次 Job 启动前都基于**当前真实资源**进行自动发现与刷新：

```text
fresh worker discovery
healthy filtering
reachable filtering
current free memory
resource refresh before each job
```

正常 automatic mode 不允许要求用户提供：

```text
world_size
GPU count
host count
stage count
min workers
```

## 必须实现 / 验证

1. 添加/完善 regression tests：
   - unreachable worker 不应进入 automatic candidate pool；
   - unhealthy worker/GPU 不应进入 candidate pool；
   - free memory 来自当前 snapshot，而非 GPU total memory 或旧 snapshot；
   - 下一个 Job 前必须 refresh resource snapshot；
   - automatic mode 不依赖固定 Host/GPU 数量。

2. 实际执行：

```bash
pytest tests/integration/test_generic_resource_discovery.py tests/unit/test_resource_manager.py
```

如果 integration 默认 skip，使用仓库已有 integration opt-in 方式重跑。

3. Phase 7 开始前做一次真实连接目录 + discovery preflight：
   - 连接端点只从 `tests/address.json` 读取；
   - 实际记录由 ShardGrid fresh discovery 得到的 reachable/healthy Host/GPU；
   - 不把 `address.json` 中静态 `gpu` 字段当作 discovery 结果；
   - 确认 Control Plane/Worker 使用能导入 PyTorch 的正确运行环境。

真实 discovery 结果可以作为运行 evidence，但不要提交任何明文凭据。

Acceptance：

```text
FRESH_RESOURCE_DISCOVERY=PASS
```

如果真实 discovery 无法得到后续硬件测试所需的健康 GPU，只能如实记录；T061 的 discovery contract 可 PASS，但 T062 将 BLOCKED。


## 真实硬件执行规则

本阶段不是模拟验收。需要硬件语义的 Task 必须真实执行。

真实机器连接信息只从：


读取。

规则：

- 不把密码/认证信息复制到源码、测试、artifact、日志、commit message 或最终报告。
- 不主动打印完整凭据。
- `address.json` 只是连接目录；其中的 `gpu` / `gpu_model` / hostname 不能替代 fresh discovery。
- 当前 Host/GPU 数、健康状态、当前 free memory、网络可达性必须由 ShardGrid 当前生产 discovery/live-preflight 重新确认。
- 不硬编码 world_size、GPU count、host count、rank count、partition count、placement。
- 每个正式 Job 走正常 Automatic Path；不能由测试脚本手工决定 GPU/rank/partition placement。
- Runtime 必须执行 Planner 选中的 exact `original-parallel-plan.json`，不得重新 repartition 或 round-robin placement。

- `MEMORY_REJECT` 可以作为 candidate admission 结果；`FORMAL_TRAINING_OOM_COUNT` 必须保持 0。

- 只清理由本次测试明确创建的 training/probe process 和 reservation。
- 如果当前 Task 所要求的真实硬件条件不存在或无法访问，必须 `STATUS=BLOCKED`；不得用 mock/单机结果代替。

# T065 — Preserve multiple jobs per GPU when admitted

Phase: Phase 7  
Priority: P1  
Depends on: T064

文件：

```text
tests/multi_host/test_generic_multi_job_sharing.py
src/shardgrid/planner/placement.py
src/shardgrid/control/job_manager.py
```

## 目标

真实验证：

> 当 fresh free-memory + real probe evidence 允许时，一个物理 GPU 可以同时承载 Job A、Job B、Job C。

不能回归：

```text
one GPU = one job
```

## 必须执行

- fresh discovery 当前所有 healthy/reachable GPU。
- 每加入一个 Job 前重新读取 ResourceSnapshot/free memory。
- 每个 Job 都走正常 Automatic Path 和 real one-batch probe。
- 不由测试代码手工 pin GPU/rank/partition。
- 选择足够小且有意义的 non-zoo/generic workload，使真实 admission 有机会允许共享；不能伪造 placement。
- 至少验证三个独立 Job 的 lifecycle/evidence；Acceptance 的关键是**同一 GPU 在被 admission 允许时出现多 Job 并存**。
- 对共享 GPU 记录 machine-readable：
  - Job IDs
  - selected plan/partitions
  - before/after free memory
  - probe result
  - optimizer step progress
- 已成功 Job 保持运行，不得为了下一个 Job 腾显存而手工杀掉。
- Formal training OOM 必须为 0。
- 若真实资源状态使三个 Job 无法被合理 admission，不能强制 placement；应按真实 memory/resource evidence 处理，并判断是 BLOCKED 还是测试设计需要在当前 Task 范围内修正。

执行：

```bash
pytest tests/multi_host/test_generic_multi_job_sharing.py
```

必须真实执行硬件路径，skip/mock 不算 PASS。

Acceptance：

```text
MULTI_JOB_GPU_SHARING=PASS
```

最终 evidence 应明确证明：

```text
CROSS_JOB_GPU_SHARING=true
```

而不是只证明三个 Job 分别跑在三张不同 GPU 上。

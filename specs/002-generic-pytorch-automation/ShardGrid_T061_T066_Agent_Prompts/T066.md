# T066 — Validate 4G to 512M stress bands

Phase: Phase 7

## 目标

在前面 single-GPU / multi-GPU / multi-host / multi-job-sharing 全部真实 PASS 后，执行低显存到饱和的真实 packing stress：

```text
Fresh Discovery
→ MEM_4G / MEM_3G
→ refresh ResourceSnapshot
→ MEM_2G
→ refresh
→ MEM_1G
→ refresh
→ MEM_512M fragment fill
→ final 512M saturation round
→ all active jobs +20 optimizer steps
→ checkpoint sampling
→ cleanup
```

使用现有已校准的 stress catalog；不要重新设计 MICRO/TINY/SMALL catalog，也不要重新校准全部 38 个配置，除非真实代码/硬件证据明确证明 catalog 已失效。

## 必须遵守

- 不预设 GPU/Host 数，fresh discovery 实际发现多少就使用多少。
- 每个 Job 走 Automatic Path。
- 每个 Job 都重新走 real memory probe。
- 每加入一个 Job 后刷新当前 free memory。
- 4G/3G 放不下不能立即结束；继续尝试 2G → 1G → 512M。
- 成功 Job 应保持长期训练；达到 ready 后至少有真实 optimizer progress evidence。
- 达到最大并发点后，所有 active formal jobs 再至少 `+20 optimizer steps`，证明持续进展与稳定性。
- Probe `MEMORY_REJECT` 可以出现。
- `FORMAL_TRAINING_OOM_COUNT=0`。
- 不因 Top-K / `NO_FEASIBLE_PLAN` 就宣布 GPU memory saturation。
- bounded search coverage 不足时必须：
  - `SEARCH_BUDGET_LIMIT`
  - 或 `SATURATION_NOT_PROVEN`
- CPU/process/network/test-limit/runtime 若先成为瓶颈，应输出真实瓶颈类型。

## GPU_MEMORY_SATURATION 证据

只有证据充分才允许：

```text
GPU_MEMORY_SATURATION
SATURATION_PROVEN=true
```

至少检查：

- 较大 bands 已实际尝试；
- 最终多个不同 family 的 512M workload 无新 feasible plan；
- remaining plausible candidates 被 static/calibration/probe 明确拒绝；
- 没有明显“GPU 尚有足够空间但 search 未覆盖”的情况；
- CPU/process/network/test-limit 没有先饱和；
- 最终 free memory/stranded memory 可解释。

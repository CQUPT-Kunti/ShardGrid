## 目标

Stress runner 只有在证据充分时才允许输出：

```text
GPU_MEMORY_SATURATION
```

证据不足时必须输出：

```text
SATURATION_NOT_PROVEN
```

或：

```text
SEARCH_BUDGET_LIMIT
```

## GPU saturation 必须考虑

至少把以下 evidence 纳入机器可读结果：

- 较大 memory bands 的实际尝试结果；
- 最终 512M fill round；
- 不同 stress families 的覆盖；
- candidate search coverage；
- static/calibration/probe reject reason；
- fresh free memory；
- remaining plausible candidates；
- CPU/process/network/test-limit 是否先成为瓶颈；
- active jobs 的 progress/stall；
- cleanup 状态；
- checkpoint sampling evidence。

不能因为：

```text
Top-K 都失败
NO_FEASIBLE_PLAN
当前 Job 数看起来很多
```

就宣布 GPU memory saturation。

如果某 GPU 仍有明显足够的 free memory，而 candidate search 根本未覆盖，必须是：

```text
SATURATION_NOT_PROVEN / SEARCH_BUDGET_LIMIT
```

## Checkpoint sampling

Stress output 必须支持机器可读 checkpoint evidence。按现有 catalog/runner 能力，抽样应覆盖有代表性的 band（例如大/中/512M，存在时），并记录 merge / strict-load / validation-forward 结果，而不是仅记录“文件存在”。

本 Task 重点是**实现证据逻辑和 integration coverage**，不是提前完成 Phase 7 的长期真实 multi-host packing acceptance。

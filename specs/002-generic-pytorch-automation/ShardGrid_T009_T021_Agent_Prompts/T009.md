# 任务目标

把 Parameter / Buffer 从 execution node 中独立出来，建立显式 state ownership 记录。最终 graph 必须能表达：某个 state 是参数还是 buffer、它原来的 `state_dict` key、shape/dtype、是否 requires_grad、共享/绑权重组、以及被哪些 execution node 使用。

# 允许修改的主要文件

```text
src/shardgrid/planner/generic_graph.py
tests/unit/test_generic_graph_ir.py
```

# 必须按以下方式实现

1. 阅读当前 `GraphNodeSpec`、`ParameterUseSpec`、`GenericGraphIR`、`_parameter_schema()`、`_buffer_schema()`、`_parameter_owners()`、`_parameter_uses()`。
2. 在 `generic_graph.py` 中增加与现有 `*Spec` 风格一致的 state dataclass。按照 `data-model.md` 的 `StateObject` 语义实现字段：
   - canonical state ID；
   - kind=`parameter|buffer`；
   - original `state_dict` key；
   - shape、dtype、requires_grad；
   - storage/shared-group ID；
   - owner evidence / use sites。
3. Parameter 与 Buffer 都必须进入新 state 记录；不能只做 parameter。
4. 对 shared/tied Parameter：多个 key 可以映射到同一 canonical state/storage group，但 checkpoint canonical owner 必须可唯一确定。
5. 新 ownership 数据不得依赖 `named_modules()` 的顺序；`named_parameters(remove_duplicate=False)` / `named_buffers(remove_duplicate=False)` 可以用于枚举 metadata 和识别共享对象。
6. 在本 Task 保留现有 `parameter_owners`、`parameter_uses`、`shared_parameter_ids` 等 legacy 字段以兼容旧调用；不要在 T009 做大规模删除迁移。
7. 更新 `GenericGraphIR.to_dict()`，保证新 dataclass 可以稳定序列化。
8. 添加单测覆盖：普通 parameter、buffer、shared/tied parameter、state use record，并明确证明 owner/use 记录不依赖 module registration order。

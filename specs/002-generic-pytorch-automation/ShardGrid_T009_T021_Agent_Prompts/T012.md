# 任务目标

扩展 `ModelProfile` / memory accounting，使 execution-node activation/value cost 与 Parameter/Buffer state cost 分开记录；`named_modules()` 只能提供 metadata，不能再作为 partition order 的事实来源。

# 允许修改的主要文件

```text
src/shardgrid/engines/models.py
src/shardgrid/planner/memory.py
tests/unit/test_model_profile_memory.py
```

# 必须按以下方式实现

1. 阅读 `ModuleProfile`、`ModelProfile`、`build_model_profile()`、`_profile_modules()`、`estimate_stage_memory()`。
2. 保留旧字段/序列化兼容，避免一次性破坏旧测试；新增字段必须有合理默认值。
3. 把内存语义至少拆成：
   - execution-node activation/temporary/compute related cost；
   - graph-value activation/transfer bytes；
   - state-object parameter/buffer bytes。
4. Parameter/Buffer state cost 使用 T009 ownership identity；不要通过 module slice 重复计算 tied/shared state。
5. Parameterless execution node 必须可以有 activation/value cost 而 state cost=0。
6. 有 state 但没有 standalone execution node 时，state cost 仍必须被统计，不能因 hook/call-order 缺失而丢失。
7. `named_modules()` 可继续用于 module type/name metadata，但禁止决定新 partition execution order。
8. 更新 `to_dict()/from_dict()` 或 dataclass 序列化兼容路径，确保旧 artifacts/tests 不因缺字段直接失败。
9. 测试覆盖：parameterless node、buffer、shared/tied state、state owner without standalone execution node。

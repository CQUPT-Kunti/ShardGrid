# 任务目标

升级 `LogicalPartitionSpec`，让一个逻辑分区明确表达 execution nodes、输入/输出 values、owned state、read-only state 和 validation evidence，不再用一个 module-order list 同时描述执行、状态和放置。

# 允许修改的主要文件

```text
src/shardgrid/planner/planning_contract.py
tests/unit/test_planning_contract.py
```

# 必须按以下方式实现

1. 阅读当前 `LogicalPartitionSpec` / `LogicalPartitionPlan` / `PlacementPlan` 和现有 constructor usage。
2. 在保持现有 constructor compatibility 的前提下，使 LogicalPartition 至少能表达：
   - `node_ids`（execution node IDs）；
   - `input_value_ids` / `output_value_ids`；
   - owned state IDs；
   - read-only state IDs；
   - memory/transfer estimate；
   - validation evidence。
3. 现有 `parameter_ids` / `buffer_ids` 若被旧代码依赖，可作为兼容字段或清晰迁移映射；不要在 T013 直接删除所有 legacy consumers。
4. owned 与 read-only 必须语义不同：更新/保存 owner 与仅读取 state 不能混为一类。
5. `to_dict()` 必须输出新 contract 字段并保持 schema/version 行为可解释。
6. 测试覆盖：构造兼容、owned/read state 区分、node/value boundary、序列化、无 module-order 依赖。

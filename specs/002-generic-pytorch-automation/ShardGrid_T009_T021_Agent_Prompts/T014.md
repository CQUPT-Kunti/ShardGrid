# 任务目标

把 partition candidate generation 从“module slice / normalized module order”迁移为基于 execution graph topology、value dependencies 和 ownership metadata 的划分。

# 允许修改的主要文件

```text
src/shardgrid/planner/partitioning.py
tests/unit/test_partition_candidates.py
```

# 必须按以下方式实现

1. 阅读 `discover_partition_support()`、`generate_partition_candidates()`、`_normalize_traced_order()`、`_ordered_modules_for_support()`、`_build_candidate()`、dependency helpers。
2. Candidate 的顺序来源必须是 GenericGraphIR execution nodes/topology，而不是 `ModelProfile.module_order` 或 module registration order。
3. 使用 graph value producer/consumer 来确定 partition boundary；branch/fan-out/fan-in/multi-consumer 不能被线性 module slice 丢失。
4. 使用 T013 LogicalPartition fields 写入 node IDs、input/output value IDs、owned/read state IDs。
5. 使用 T011 state-use mapping：state 可被某 partition owner 持有并被其他 partition 只读使用。
6. shared/tied state 不允许因跨 partition use 被复制成多个 owner。
7. 禁止实现 `ordered_names = call_order`；也不要通过“按模型名特殊切分”通过测试。
8. 保持 bounded candidate search 现有预算语义。
9. 测试必须覆盖 residual、branch/merge、attention、dense、shared-module，断言 candidate 是 dependency order 而非 registration order。

# 任务目标

让 execution node 和 graph value 拥有稳定、可寻址的 ID，并由 producer/consumer 关系表达真实执行依赖；这些关系必须与模块注册顺序无关。

# 允许修改的主要文件

```text
src/shardgrid/planner/generic_graph.py
tests/unit/test_generic_graph_ir.py
```

# 必须按以下方式实现

1. 阅读 `_graph_from_fx()` 当前 `n####` / `v####` 的生成、`GraphNodeSpec`、`GraphValueSpec`、`GraphEdgeSpec`、`graph_fingerprint()`。
2. 保持 `CanonicalGraphIR = GenericGraphIR` 兼容。
3. 明确并固定 ID 生成规则：ID 来自 captured graph 的稳定 traversal/identity，而不是 `named_modules()` 顺序或 module path 排序。
4. 每个 execution node 必须能通过 `node_id` 唯一寻址；每个 value 必须能通过 `value_id` 唯一寻址。
5. 每个 value 必须保留 producer node ID 和所有 consumer node IDs；多消费者不能丢失。
6. Graph inputs / outputs 继续以 value ID 表达；functional op、parameterless op 也必须获得 execution node ID。
7. `graph_fingerprint()` 必须覆盖足以验证 node/value dependency 的稳定字段，同时不要依赖 Python object id。
8. 添加测试：注册顺序不同但 execution graph 相同/等价时，依赖关系仍按 graph 正确表达；branch、多 consumer、functional op 的 producer/consumer 必须正确。

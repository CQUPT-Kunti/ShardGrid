## Implementation Strategy

### MVP First

1. Complete T001-T027.
2. Complete T028-T053 in the order Environment Probe, Conda Probe, GPU/Runtime Probe, Worker Bootstrap, SSH, WSL, then PyTorch Distributed, and stop at the first hardware gate that fails, preserving diagnostics.
3. Complete T054-T075 and prove the supported model on RTX 4060 plus GTX 1060.
4. Complete T083-T105 and validate the formal one-command SSH MVP.
5. Only then begin T117-T156.

### Incremental Delivery

- Deliver the cross-platform and diagnostic foundation first.
- Deliver real distributed communication before model automation.
- Deliver the static supported model before arbitrary planning.
- Deliver the SSH backend before Kubernetes.
- Deliver Kubernetes before Volcano, and Volcano before HAMi.
- Keep every previous backend runnable when a later compatibility gate fails.

### Final Validation Rule

No task, report, CLI status, or documentation may mark a hardware or platform gate successful without live evidence from the target environment. A blocked, skipped, simulated, or fallback result must retain its explicit label and diagnostic artifacts.
